# HanaWorlds Contracts 0.5.0

Pure public contracts for the single-user local-world MVP. Import from `hanaworlds-contracts`. This is a fresh-install protocol replacement. No prior exports, peer compatibility, state migration, or permission bridge ships in this package. Earlier source and evidence remain in Git and their original run directories.

`spec/local-world/profile.json` is the authored schema and operation source. `src/local/` owns pure relation/geometry validation. `npm run build` generates `dist/local`, `types/local`, `schemas/local`, and current fixtures. Never edit those outputs directly.

Current wires: `session/v3`, `canvas/v5`, `world-adapter/v6`, `painter/v4`, `BUILD/V3`, `ReferenceBrief/v3`, `interaction-surface/v4`; compiled operations `operations/v3`; target facts `target-facts/v4`; safety profile `safety-profile/v3`. Existing projections retain the `HanaWorlds|contracts@0.4.0|` domain; the new `material-sources` projection uses `HanaWorlds|contracts@0.4.2|material-sources|`. The existing `checkContractHandshake` stays exact-package for the fixed K1/K2 compositions. Region v1 (0.5.0, below) adds `region-build/v1`, `painter-region/v1`, `world-adapter-region/v1`, `canvas-region/v1` and decides compatibility by protocol major + capabilities. Old digests are not reused.

## Region voxel block + palette v1 (0.5.0)

Additive only: all 334 earlier types, 55 operations, ownership rows, digest kinds, settings and invariants are byte-identical to 0.4.2 (`tools/compare-baseline.mjs`). Per-cell `BUILD/V3` → `operations/v3` is unchanged and remains the fine-adjustment path. No setting, threshold or scale limit is added; which write method to use is chosen by the skill from the tools' self-description.

**`RegionVoxelBlock` (`region-voxels/v1`).** `origin` is the min corner in world node coordinates (Luanti x,y,z, y up), `size` the positive x,y,z extent. `indexOrder` is `X_FASTEST_THEN_Y_THEN_Z`, i.e. `index = (x-ox) + sx*((y-oy) + sy*(z-oz))`, identical to Luanti `VoxelArea:index` and `.mts` schematic order, so Adapter maps directly onto VoxelManip data arrays. `palette` is `NodeSpec[]` sorted by UTF-16 `nodeName` then `param2`, unique, every entry used. `runs` is the canonical run-length form `[count, paletteIndex | null]` (adjacent values differ; counts sum to the cell count), so one content has exactly one encoding and one digest.

- `null` = **UNSPECIFIED**: the cell is not written and keeps node, param2 and extras. It is never carve.
- Carve is only the explicit palette entry `{nodeName:"air",param2:0}`. `ignore` (the engine's skip marker) is forbidden; `air` with param2 ≠ 0 is rejected; an all-null block is rejected.
- `validateRegionPalette(block, catalogue)` applies the same static-material rule as per-cell BUILD (known node, known definition, legal param2, no callbacks/persistent state) to every palette entry, air included.
- Helpers: `encodeRegionBlock`, `expandRegionBlock` (Int32Array, -1 = unspecified), `regionBlockBox`, `mapblockOf`, `regionChunksOfBox`, `expectedRegionState`, `summarizeRegionStates`, `expectedRegionSummary`. They are pure; no world access, compression or transaction decision.

**State and chunks.** Chunks are Luanti mapblocks (16³, `chunkEdge: 16`; an engine unit, not a policy). `RegionState` is a fully specified block (no null runs) plus sparse `extras` (metadata / inventory / timer per position) — the fields a restore needs beyond node/param2/air. param1 is derived light (`recompute-with-readback`). After a write, specified cells take the palette node and lose extras; unspecified cells keep everything (`expectedRegionState`). Region digests use the protocol domain `HanaWorlds|region-voxels/v1|<kind>|`, independent of the package version: `region-block`, `region-state`, `region-build`, `region-operations`, `region-summary`, `region-snapshot-content`.

**Flow (public seams; each role keeps its ownership).**

1. Painter `painter-region/v1 ValidateRegionProposal`: same Session/turn/intent/ReferenceBrief (media included)/Catalogue/localContext association as per-cell proposals; the result `RegionBuildProjection` carries the proposal block unchanged (`validateRegionProposalRequest/Response`). Painter validates only; it neither writes nor plans.
2. Brush `region-build/v1 CompileRegionBuild`: pure split into mapblock-aligned `RegionChunks` (`region-operations/v1`). `validateCompiledRegionSet` checks the chunks specify exactly the build's specified cells with the same node/param2, nothing outside the build box, and that unspecified never becomes air.
3. Adapter `world-adapter-region/v1`: `ReadRegion` covers every mapblock intersecting `box`; a chunk is `KNOWN` only after load (`ALREADY_LOADED` or `LOADED_BY_EMERGE`) and readback with a bound `stateDigest`; otherwise `UNKNOWN` with a reason. `requireKnownRegion` rejects any still-unknown chunk. `WriteRegion` writes per chunk after comparing `expectedCurrentDigest` (`APPLY` with ops, `RESTORE` with a full `RegionState`), returns per-chunk `WRITTEN/NOT_WRITTEN/UNKNOWN` + readback digest and a `RegionLighting` fact that is `COMPLETE` only after bulk light recalculation finished. `validateRegionWrite` returns `committed:false` always: Adapter never decides a transaction.
4. Canvas `canvas-region/v1 ApplyRegionCommit`: one logical transaction across chunks. `RegionCommitResult` is `VERIFIED` only when the complete `actualSummary` equals `expectedAfterSummary` and lighting is complete; `ROLLED_BACK` only when the actual summary equals the before summary (no residue). `RegionSnapshotRef` records the durable pre-write `RegionSnapshotContent` compressed with a mature format chosen by Canvas (`compression` name, compressed SHA-256 and length; the canonical JSON of the content is what gets compressed). `validateRegionSnapshotContent` checks content/state/summary digests after Canvas decompresses.
5. Canvas `UndoRegionCommit`: only for a `VERIFIED` origin transaction of the same world, only while the current region summary still equals the origin's verified after summary (otherwise `UNDO_CONFLICT/EXTERNAL_EDIT_CONFLICT`), and `VERIFIED` only when the restored summary equals the origin before summary.

**Protocol major + capability compatibility.** Each component advertises a `ProtocolHandshake` (`protocol-handshake/v1`): protocols `{protocol, major, minor}`, capability ids, and provenance (package name/version, source revision, artifact digest). A consumer builds `ProtocolRequirement`s (`protocolRequirement('canvas-region/v1', [caps], minMinor)`) and calls `checkProtocolCompatibility` before any write. Compatible = same major, advertised minor ≥ required, every required capability present. Provenance is returned for the record and never compared, so a different patch, source or hash of the same major interoperates. Missing protocol / different major / lower minor → `UNSUPPORTED_VERSION`; missing capability → `CAPABILITY_UNAVAILABLE`. Majors are explicit integers ≥ 1, independent of the 0.x npm version; a 0.x package version never implies compatibility, and a peer without a `ProtocolHandshake` (e.g. the exact 0.4.2 `ContractHandshake`) is rejected. Within a major, a minor may add operations, types or capability ids only; adding a field/enum value to an existing type is a new major. `contractProtocols`, `protocolPolicy`, `regionCapabilities` (id, owner, meaning) and `regionInvariants` (read-only, for the Shell management surface) are exported. No old wire/profile migration.

**Tool self-description.** `WriteMethodDescriptor` = method (`PER_CELL`/`REGION`), tool name, purpose, input type, free-text typical scale (`scaleUnit:"cells"`), required capability ids, unavailable reason. It has no threshold field by design.

**Public fixture.** `hanaworlds-contracts/fixtures/region` is an explicit hand-built SOURCE/FIXTURE scenario (fill, explicit carve, unspecified cells, 6 cross-mapblock chunks, emerge-loaded read, per-chunk write with lighting, gzip snapshot, VERIFIED commit and whole Undo, a peer handshake, two write-method descriptors). No real Painter, Brush, Adapter, Canvas, Luanti world or durable store ran to produce it.

## Local association and dispatch

`LocalWorldContext` contains the actual `connectionRef`, transport-open `connectionIncarnationRef`, selected `worldRef`, and Canvas world-selection `selectionRevision`. Adapter creates a new incarnation for each opened connection. Canvas changes the selection revision on connection/world reselection. These values correlate transport and business state; they convey no privileges, identity claims, permission, or delegated right. Read the actual connection through `ReadLocalConnection`; select using `SelectWorldConnection` with `expectedContext` (null for initial selection). `validateWorldSelection` compares the requested world/connection/incarnation to that readback. `ReadWorldSelectionContext` remains callable before a world is selected. Never invent a default incarnation.

World-bound requests carry `localContext`. Providers run strict `admitRequest` / `validateBoundRequest` and `validateCurrentRequest` using their own current state. The latter returns `EXECUTE` or `RETURN_STORED`; a completed duplicate returns the recorded outcome and cannot cause a second write. Provider storage owns durable reservation and outcome persistence. `LocalRequestFacts` is an internal function argument read from provider state, never a client credential or model tool payload. Current turn/brief and current connection must be re-read before consuming a result. No serialized value establishes live truth.

The Host binds internal ports: model → Workshop proposal tool → Painter → pure Brush → Canvas. Adapter mutators are exposed only on the internal Canvas dispatch port. Contracts describe this ownership and check payloads; they do not authenticate transports or enforce process access. A `callerRole: "Canvas"` field is not a substitute for internal dispatch and is not accepted. Painter and Brush never write the world; the model cannot invoke Adapter mutators.

## Build and transaction flow

1. Workshop supplies the current confirmed brief, bounded proposal context and live local facts. Painter calls `validateBuildProposalContext`, performs its BUILD construction, then `validateBuildProposalResponse`. Protected-region and game-privilege checks are absent. Physical body clearance, coverage, materials, hazards and geometry remain. Placement uses `CURRENT_VIEW` or a `PICKED_POINT`; online-user authorization and named-player choice are absent.
2. Brush consumes `BUILD/V3`, validates exact effects, and returns `operations/v3`. The declared BUILD, frame, catalogue, facts, safety and compilation digests must match. Contracts do not run a compiler.
3. Workshop uses `CurrentBuildSubmission` / `validateCurrentBuildSubmission` to correlate the current advance, intent, Canvas affected-object analysis and apply request. This replaces the former authorization derivation. Existing-object conflicts reject this fresh-build entry. Canvas owns further decision, registry, inspection-record and revision checks.
4. Canvas reserves a single transaction, reads real occupied footprints, and passes `ScopedWorldBinding` to Adapter prepare/apply. The scoped payload binds the exact local context, operation, checked cells, existing object footprints and saved before image. `projectScopedPreparedTransaction` projects the prepared result for apply. Caller-supplied prepared state is forbidden at the Canvas apply port.
5. Canvas obtains actual complete readback. `validateCommitReadback(receipt, expectedReadback, actualReadback, durableHistory)` checks equality, digest and same-transaction durable history. The expected state must come from Canvas/Adapter compilation or the saved before image, actual state from Adapter, and history from Canvas's durable store. For rollback, compare the complete saved before-state readback and pass null history. Pending/unknown is not verified success. These pure checks never prove real reads or durable persistence themselves.
6. History Undo retains the original transaction, saved before image, before/after readback digests, current state and history revisions. Workshop `UndoCurrentBuild` resolves the current verified build; Canvas owns same-transaction Undo, conflict checks and durable linked history. Adapter only transports it. Existing recovery shapes remain available for future work, but RPC recovery, timeout reentry, concurrency and extensive counterexample matrices are deferred and are not tested by this MVP gate.

## Evidence

`npm test` exercises the normal public chain and its core boundaries only. `npm run typecheck` checks an independent typed consumer surface. `tools/gate-local-world.sh <full-source-sha> <evidence-directory>` archives the exact source, installs from the lock, builds, verifies deterministic outputs, runs the source gate, packs the real tarball and installs it in a separate consumer. All results are SOURCE/FIXTURE, with no real model, world, UI or product acceptance claim.

Shell management consumers also render `placementSettingDescriptors`, `placementInvariants`, and `settingsSurface`. The four existing placement defaults remain 2/16/8/4; removing permissions does not hide geometry settings or correctness invariants. The current schema/profile export is the complete per-operation field inventory.

The existing Adapter lifecycle `acquire` port now has the shared `LocalWorldAcquireInput` shape `{connectionRef, requesterRef, userPath, action}`; neither username nor password is accepted. `LocalWorldQuery` and `LocalWorldObservation` describe its inspect handle and actual current process/world result. `worldRef` may be null before payload provisioning. `LocalWorldLifecycleAction` selects provisioning or connection work, not a permission. `leaseRef` is a finite process-operation handle, not a grant or an Adapter mutation credential.

The existing Host control service is described by `NativeControlInput` `{requesterRef,worldPath,userPath,operationRef}`, `NativeControlLease` `{controlRef,worldPath}`, `NativeControlQuery` `{controlRef,requesterRef,worldPath,operationRef}` and `NativeControlEvidence` `{state,worldPath,processId,operationRef}`. `LocalEngineControlPort` declares its acquire/inspect/withStoppedWorld methods. These match the observed Desktop no-credential source shape; no username, password or engineActorName is supplied or read. Paths must be canonicalized by the owning runtime, and CURRENT/STOPPED facts must come from its actual child lifecycle, with STOPPED valid only inside its callback. Adapter must remove facts.username equality and engineActorName from observations, and correlate the actual process/world/operation instead. No new wire, tool or lifecycle implementation is introduced here. After pairing, actual transport incarnation is read through ReadLocalConnection.

## 0.4.1 image proposal correction

`BuildProposalContext.referenceBrief.media` and `ValidateBuildProposalRequest.referenceBrief.media` retain the complete, already-verified MediaBinding array. The text-only empty-array rule is removed. Fields, wire versions, geometry, ownership and digest projection definitions are unchanged; their 0.4.0 digest domain remains the current schema domain, not a compatibility adapter. That fix shipped in 0.4.1 and remains in 0.4.2; current package discovery advertises **hanaworlds-contracts@0.4.2** and rejects mixed package versions.

Workshop/Host must read the actual attachment bytes, recompute storedBytesDigest, check media type/dimensions and associate the attachment with the current Session before supplying sourceContext/currentContext. The pure contracts package has no attachment store and cannot establish this provenance from caller JSON. It verifies the complete media-bearing brief digest, intent linkage, current Session/turn/world, source/current context equality and paired projected-byte fields. A client changing the stored digest and rehashing its own brief still cannot replace the provider's current verified brief. Keep media in the same skill model channel and in the public context; do not strip it to reach Painter. Painter remains a pure geometry validator/assembler, not an image-planning model.

For the image assembly, all five origins pin the exact new tar: Workshop preserves verified media in source/current context; Desktop preserves the media channel and supplies current verified facts; Painter consumes nonempty media with the same validators; Canvas and Adapter change only the image assembly's contract pin/handshake, with no transaction/transport field change. Brush likewise uses the exact image-assembly package. Keep the fixed text build on its existing 0.4.0 pins until separately coordinated. No palette/texture protocol is added.

Focused reproduction: `tools/gate-image-proposal.sh <full-source-sha> <absolute-evidence-dir>`. It runs only the affected image/text proposal checks and core media/Session/world boundaries, actual npm pack/install and a typed image consumer; it does not rerun the previous 16-case local-world suite. The former gate and tests remain source history and are not this image delivery's evidence.

## Readonly material sources (0.4.2)

`MaterialSourceFactsPort.readMaterialSources(worldRef)` is an additive in-process method of the existing `hanaworldsLuantiNativeFacts` service. It returns `{snapshot, textures}`. `snapshot` is strict JSON, `textures` is a list of `{bytesDigest, bytes: Uint8Array}` containing exactly one blob per distinct KNOWN digest. It is not a model argument, MediaBinding, Resource or mutating wire. No wire operations changed.

Host calls `validateMaterialSources(response, freshCatalogue, freshConnection)`; `freshConnection` has exactly worldRef, connectionRef and connectionIncarnationRef, projected from its current selection. The pure check binds the Catalogue digest/game identity, exact node name/definitionRevision/legal param2, sourceRevision, raw SHA256 and byte length. It cannot attest a runtime provider, decode an image or establish currentness by itself. Adapter must inspect the actual paired world/incarnation before and after its read, resolve the actual server game/mod texture source, and return a coherent snapshot or fail on connection/source changes. Host must recheck current selection and fresh Catalogue before consuming or caching the result. A persisted JSON snapshot alone is insufficient.

`sourceRevision = digestValue('material-sources', projection).sha256`, where projection is the snapshot with only sourceRevision removed. Rows are sorted by UTF-16 nodeName then numeric param2, with null first; duplicate keys are invalid. The digest includes source paths/names and actual byte digests, so changed bytes invalidate the revision even when the node registry revision stays constant. `sourceRef` is the resolved logical game/mod origin (for example `fixture-mod/textures/fixture_stone.png`), never a credential or public URL. Shared identical bytes may serve multiple rows. Omitted nodes have no known material source and must not be guessed.

KNOWN means the provider has verified an identical, unmodified, non-animated texture on all rendered faces, resolved source precedence and no appearance-changing animation, tint, palette, overlay or modifier. The source basis is explicitly SERVER_ASSET_ONLY: no claim about client texture packs or personalized rendered appearance. Any unverified source, override or effect is UNKNOWN with a reason and null texture; unknown legal param2 and definitionRevision remain null, never guessed as zero or a registry fallback. A non-null param2 always belongs to Catalogue.allowedParam2. PNG/JPEG/WebP byte formats still require Painter decoding. Unsupported rendering stays UNKNOWN; no renderer or RGB values are supplied here.

KNOWN describes texture provenance only. It never fills unknown static capability fields or authorizes a build. Painter must still run `validateStaticMaterials` on candidates; Canvas and Brush retain their existing validation. UNKNOWN/no usable static candidate produces an explicit unavailable result, not a fixture alias, default color or external game match. Adapter supplies actual bytes; Painter reuses its existing pure measurement; Desktop connects current facts; Workshop preserves media and confirmed material inputs. Canvas/Brush only update the exact shared image pin/handshake. No peer imports or peer code changes ship here.

Validation returns frozen JSON/records and owned copies of the byte arrays. Typed array elements remain mutable: decode those copies or revalidate after editing them; do not treat the returned wrapper as immutable pixel storage. JSON serialization is only for the snapshot, never the byte envelope.

Run `npm run test:materials`, `npm run typecheck:materials`, and `npm run verify:source` after build. `tools/gate-material-sources.sh FULL_SOURCE_SHA ABSOLUTE_EVIDENCE_DIR` verifies a clean archived source, deterministic generation, an actual tarball and an independently installed typed consumer. This is SOURCE/FIXTURE evidence; actual Adapter/Luanti and product UI gates belong to their writers.
